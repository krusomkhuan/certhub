# CertHub — วิทยาลัยการอาชีพโพนทอง

เวอร์ชัน **1.0.0** · 29 ตุลาคม 2569 · ดู [บันทึกการเปลี่ยนแปลง](CHANGELOG.md)

ระบบ PHP + SQLite สำหรับ XAMPP ไม่ต้องติดตั้ง Composer หรือ Node.js

## เริ่มใช้งาน

1. เปิด Apache ใน XAMPP แล้วเข้า http://localhost/certhub/
2. เลือก “สำหรับผู้ดูแลระบบ” และสร้างบัญชีแรกจากเครื่องเซิร์ฟเวอร์ รหัสผ่านขั้นต่ำ 12 ตัวอักษร ไม่มีบัญชีหรือรหัสผ่านเริ่มต้น
3. สร้างโครงการ ระบุวันเริ่ม–สิ้นสุด สถานที่ และผู้รับผิดชอบ ระบบสร้างเทมเพลต 4 ประเภทให้อัตโนมัติ
4. เพิ่มรายชื่อ หรือดาวน์โหลด CSV ตัวอย่างและนำเข้าไฟล์ CSV UTF-8 จาก Excel
5. ปรับเทมเพลตและผู้ลงนาม ออกเกียรติบัตร แล้วเปิดเผยแพร่โครงการเพื่อให้หน้าบ้านค้นหาได้
6. กรอกวัตถุประสงค์ ผลการดำเนินงาน ปัญหาและข้อเสนอแนะ พร้อมภาพและคำบรรยายในแท็บรายงาน

ผู้รับผิดชอบเป็นข้อมูลของโครงการ ปัจจุบันการแก้ไขทั้งหมดทำโดยบัญชีผู้ดูแล ยังไม่มีบัญชีและสิทธิ์แยกสำหรับผู้รับผิดชอบแต่ละคน

## เกียรติบัตรและรายงาน

- รองรับผู้เข้าอบรม วิทยากร คณะกรรมการดำเนินงาน และผู้รับเกียรติบัตรทั่วไป
- ค้นหาโดยชื่อ-นามสกุลตรงตามที่ลงทะเบียน หรือเลขที่เกียรติบัตรที่ผู้ดูแลกำหนด
- เปิดหน้ารายบุคคลแล้วเลือกพิมพ์ / บันทึก PDF ผ่านเบราว์เซอร์ เกียรติบัตรใช้ A4 แนวนอน รายงานใช้ A4 แนวตั้ง
- เลือกเปิดกราฟิกพื้นหลังและปิดหัว/ท้ายกระดาษของเบราว์เซอร์เมื่อต้องการ PDF เกียรติบัตร
- รายงานสรุปจำนวนจากรายชื่อที่บันทึก ไม่ใช่ข้อมูลเช็กชื่อเข้าร่วมจริง
- ภาพกิจกรรมและรายงานเข้าถึงได้เฉพาะผู้ดูแล

## Canva

ดาวน์โหลดพื้นหลัง SVG จากแต่ละเทมเพลต นำไปอัปโหลดและแก้ไขใน Canva แล้วส่งออกเป็น PNG/JPG อัปโหลดกลับเข้าสู่ CertHub โดยเว้นบริเวณข้อความผู้รับไว้ ระบบวางชื่อ โครงการ วันที่ และผู้ลงนามทับพื้นหลังให้อัตโนมัติ สามารถเก็บลิงก์ Canva เพื่อกลับไปแก้ไขได้

ยังไม่มี OAuth / Canva Connect API / การซิงก์กลับอัตโนมัติ หากต้องการต้องลงทะเบียน Canva integration และตั้งค่าบัญชี/สิทธิ์เพิ่มเติม: https://www.canva.dev/docs/apps/rest-apis/autofill-guide/

## ข้อมูลและการดูแล

- PHP 8.1+ พร้อม pdo_sqlite, mbstring และ fileinfo
- SQLite และไฟล์ภาพอยู่ใน `data/` ต้องสำรองทั้งโฟลเดอร์ขณะไม่มีการเขียนข้อมูล
- Apache ต้องอนุญาต `.htaccess` ของ `data/` เพื่อป้องกันดาวน์โหลดฐานข้อมูล ห้ามเปิดโฟลเดอร์นี้เป็น static directory บนเซิร์ฟเวอร์อื่น
- เปิด HTTPS ก่อนให้ใช้งานผ่านอินเทอร์เน็ต ตั้งค่าบัญชีแรกจาก localhost ก่อนเปิดระบบให้ผู้อื่นเข้าถึง
- ใช้ prepared statements, password hashing, session regeneration, CSRF และตรวจชนิด/ขนาดไฟล์ภาพ
- ใช้ฟอนต์ที่ติดตั้งในเครื่อง ไม่มีการเรียก Google Fonts จากเว็บ

## การทดสอบ

รัน `python tests/registry.py` เพื่อทดสอบบนสำเนาระบบและฐานข้อมูลชั่วคราวแยกจากข้อมูลจริง รวมการออกเลขพร้อมกัน คำร้อง สิทธิ์บัญชี และ regression tests

ทดสอบ login, ผู้รับผิดชอบ, เทมเพลต 4 ประเภท, CSV/รายชื่อซ้ำ, ออกและเผยแพร่, ค้นหา, รายงาน, ภาพกิจกรรม, ส่งออก SVG, เพิกถอน, ป้องกันฐานข้อมูล และ CSRF


## เลขที่เกียรติบัตรและช่วงวันที่

เมนูหลัก “ออกเลขที่เกียรติบัตร” → ตั้งค่ารูปแบบเลขกลางทั้งวิทยาลัย เช่น `วอ.โพนทอง/{year}/{seq}` โดย `{year}` คือปี พ.ศ. วันที่ออกเลข และ `{seq}` คือลำดับกลางทั้งวิทยาลัย ไม่รีเซ็ตเลขเมื่อเปลี่ยนปีและห้ามย้อนลำดับ

ทุกงานและคำร้องใช้ตัวนับเดียวกัน มี SQLite write transaction และ unique indexes สำหรับเลขที่และลำดับกลาง ทดสอบออกพร้อมกัน 6 กระบวนการแล้วไม่ซ้ำ เลขเดิมและเลขเพิกถอนคงเดิม เลขเก่าที่ชนกันจะทำให้ยกเลิกการออกทั้งชุดเพื่อให้ผู้ดูแลปรับลำดับ

มีแบบลงทะเบียนเลขที่อย่างเดียว (ไม่ต้องมีไฟล์ ไม่สร้างเอกสารหรือเผยแพร่ QR) และแบบออกเลขพร้อมสร้างเอกสาร งานทุกประเภทบันทึกวันเริ่ม–สิ้นสุดได้

## QR Code

ตั้งค่า / สำรองข้อมูล → URL ของ CertHub ใส่ URL ที่ผู้รับเข้าถึงได้ เช่น HTTPS ของวิทยาลัย หรือ IP ภายในสำหรับทดสอบ ไม่ใส่ index.php หรือ query string เมื่อออกและเผยแพร่เกียรติบัตรแล้ว ระบบแสดง QR ลิงก์ตรวจสอบรายฉบับ การเพิกถอนหรือปิดเผยแพร่จะทำให้ลิงก์เปิดไม่ได้

QR สร้างในเบราว์เซอร์ด้วย qrcode-generator (MIT, ดู assets/qrcode-LICENSE.txt) โดยไม่ส่งข้อมูลไปบริการ QR ภายนอก ลิงก์ localhost ใช้ได้เฉพาะเครื่องเดียว การเปลี่ยน URL ภายหลังต้องรักษา redirect จาก URL เดิมหรือพิมพ์เอกสารใหม่

## PDPA

มีหน้านโยบาย `?page=privacy` และลิงก์ท้ายเว็บ เริ่มต้นเป็นฉบับร่าง ให้ผู้ดูแลระบุช่องทางรับคำขอและฐานการประมวลผลที่วิทยาลัยใช้จริง จากนั้นยืนยันประกาศใช้ในหน้าตั้งค่า เก็บรักษาแบบไม่กำหนดวันสิ้นสุดตามข้อกำหนดผู้ใช้ แต่ต้องทบทวนความจำเป็นและดำเนินการตามคำขอใช้สิทธิ ไม่มีการลบตามอายุอัตโนมัติ และการอ่านนโยบายไม่ถือเป็นความยินยอม

## สำรองข้อมูล

ผู้ดูแล → ตั้งค่า / สำรองข้อมูล → ดาวน์โหลดไฟล์สำรอง ZIP เป็น snapshot ฐานข้อมูล SQLite พร้อมไฟล์ภาพที่อ้างอิง เทมเพลต ไฟล์โปรแกรม การตั้งค่า และบัญชีผู้ดูแล มี manifest SHA-256 และ RESTORE.txt อยู่ใน ZIP ไม่ต้องติดตั้งส่วนขยาย ZipArchive (ใช้ PharData)

ไฟล์ ZIP ไม่ได้เข้ารหัส ต้องเก็บในพื้นที่จำกัดสิทธิ์ ระบบลบไฟล์ชั่วคราวหลังส่งดาวน์โหลด ไม่มีระบบกู้คืนผ่านหน้าเว็บ การกู้คืนให้ปิด Apache เก็บชุดเดิมแยกไว้ แตก ZIP และตรวจ checksum/สิทธิ์ data/.htaccess ก่อนเปิดระบบ ตรวจฐานข้อมูล ภาพ และ URL รวมถึงนำคำขอลบ/จำกัดการใช้ข้อมูลกลับมาประกอบการกู้คืนเสมอ

## ปรับขนาดตัวอักษร

ปุ่ม ก− / ก / ก+ บนแถบด้านบน ลดขนาด คืนค่าเริ่มต้น และเพิ่มขนาดได้ตั้งแต่ 90–150% ครั้งละ 10% จำค่าในเบราว์เซอร์ด้วย localStorage หากปิดการเก็บข้อมูลยังปรับได้ในหน้าปัจจุบัน ขนาดเอกสารเกียรติบัตรและงานพิมพ์ไม่เปลี่ยนตามค่านี้

## แก้ไขโปรไฟล์ผู้ดูแล

เมนู “แก้ไขโปรไฟล์” (`?page=profile`) ใช้เปลี่ยนชื่อที่แสดง อีเมลติดต่อ ชื่อผู้ใช้ และรหัสผ่านของบัญชีที่เข้าสู่ระบบเท่านั้น การเปลี่ยนชื่อผู้ใช้หรือรหัสผ่านต้องยืนยันรหัสผ่านปัจจุบันและจะยกเลิกเซสชันในเครื่องอื่น เว้นช่องรหัสผ่านใหม่ว่างเพื่อคงรหัสเดิม อีเมลยังไม่ใช้กู้คืนรหัสผ่าน ทดสอบด้วย `python tests/profile.py`

## ผู้ดูแลระบบสำรอง

เมนูผู้ดูแลระบบสำรอง (`?page=admins`) แสดงบัญชีผู้ดูแลและเพิ่มบัญชีใหม่ได้ ระบุชื่อ อีเมล (ไม่บังคับ) ชื่อผู้ใช้ และรหัสผ่าน พร้อมยืนยันรหัสผ่านของผู้สร้าง ผู้สร้างเลือกบทบาทผู้ดูแลหลัก เจ้าหน้าที่งานบริหารงานทั่วไป หรือผู้ดูรายงานได้ ระบบไม่ส่งอีเมลหรือแสดงรหัสผ่านที่บันทึกไว้ และไม่เปลี่ยนบัญชีที่กำลังเข้าสู่ระบบหลังเพิ่มบัญชีใหม่

## คำร้อง คู่มือ และสิทธิ์

- `?page=request`: แบบคำร้องสาธารณะ ไม่ต้องแนบไฟล์ กรอกผู้ขอ หน่วยงาน ติดต่อ งานและจำนวนเลขที่ 1–5,000 เลข โดยไม่เก็บรายชื่อผู้รับในคำร้องใหม่ ส่งแล้วเก็บลิงก์ส่วนตัวเพื่อติดตามผล/พิมพ์คำร้อง
- `?page=requests`: เจ้าหน้าที่หรือผู้ดูแลหลักพิจารณา อนุมัติแล้วออกเลขกลางครั้งเดียวตามจำนวนที่ขอ ไม่อนุมัติได้โดยระบุเหตุผล
- `?page=guide`: คู่มือบนเว็บ พร้อมพิมพ์/บันทึก PDF
- `?page=reports`: ดูภาพรวม กรองประเภทงาน เปิดรายงานและภาพประกอบ
- `admin`: ผู้ดูแลหลักจัดการระบบทั้งหมด
- `registry`: เจ้าหน้าที่งานบริหารงานทั่วไปจัดการเลขกลาง งานที่รอเลข และคำร้อง ดูรายงานและแก้โปรไฟล์ตนเองได้
- `report_viewer`: รองผู้อำนวยการฝ่ายบริหารทรัพยากรดูและพิมพ์รายงาน แก้โปรไฟล์ตนเองได้ ไม่มีสิทธิ์แก้ไขงานหรือออกเลข

หลังคืนฐานข้อมูลจากสำรองเก่า ต้องกระทบยอดเลขที่ออกภายหลังและตั้งลำดับถัดไปให้พ้นทุกเลขที่เคยออก ก่อนเปิดให้ออกเลขใหม่ ข้อมูลที่ไม่อยู่ในชุดสำรองไม่สามารถตรวจซ้ำได้จากฐานข้อมูลเก่า

## ออกเลขหลายรายการ

เมนูออกเลขที่เกียรติบัตรรองรับรายชื่อหนึ่งคนต่อบรรทัด 1–5,000 คนต่อครั้ง มีตัวนับและตรวจชื่อซ้ำ จัดสรรทั้งชุดใน transaction เดียว แสดงช่วงเลขและจำนวนหลังสำเร็จ แบบฟอร์มมี nonce ป้องกันส่งซ้ำหลังสำเร็จ

หลังบ้านมีปุ่ม “หน้าเว็บไซต์” ด้านบนเพื่อเปิดหน้าบ้านในแท็บใหม่

หน้าบ้าน คำร้อง คู่มือ และ PDPA แสดงมุมมองสาธารณะเสมอแม้เข้าสู่ระบบอยู่ เมนูและชื่อบัญชีผู้ดูแลแสดงเฉพาะหน้าหลังบ้าน โดยไม่ออกจากระบบหรือเปลี่ยนสิทธิ์ของบัญชี
